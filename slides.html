Vibe Coding a Hackathon

…and actually seeing what your AI did, with Drawa

1

TL;DR

  • Ship a demo, not a codebase. Judges see 3 minutes of your app.
  • One core flow. Not in the demo? Don't build it.
  • Plan before code. Argue with the plan, not 500 lines.
  • Commit every time it works. Git is your undo button.
  • Know what the AI changed. Can't explain it? Can't defend it.
1

Scope + prompting

  • One-sentence pitch, one core flow, boring stack (Next.js, Supabase, Vercel)
  • Rules file the agent reads every session: CLAUDE.md / AGENTS.md
  • Small asks. One feature per prompt.
  • Show, don't describe: screenshot, sketch, exact error
  • Define "done": "Click Submit → see 5 quiz questions."
½

The problem

  • 4 teammates, 4 agents, one repo
  • Each agent's work scrolls past in a terminal
  • Which files did it touch? What did it delete? Who broke the build?
  • You find out on stage.
½

Drawa: your AI's work, drawn as a map

Two sessions, a plan under review, approvals, files and commands, each wired to its card.

1

1 · Argue with the plan, not the code

  • In plan mode the agent's plan lands on the canvas as a document
  • Comment on any block, or draw on it
  • Send it back → next version shows exactly what changed
  • Approve only when it's right. Then it codes.

10 minutes of planning saves 2 hours of undoing.

1

2 · Parallel sessions, one canvas

  • Frontend agent, backend agent, bug-fix agent: side by side
  • See instantly when two agents touch the same file
  • Sub-agents get their own window. Message them directly.
  • Type any time: messages queue while the agent works
  • Reload or close the laptop: sessions resume
½

3 · Review before you demo

  • Every edit from every session, one click away as a diff
  • Catch the AI "fixing" a bug by deleting the feature
  • Git window built in: status, history, commit messages written for you
  • GitHub: PRs, issues, failing CI checks → straight to the agent
½

4 · A whiteboard around your code

  • Sticky notes, Markdown docs, Mermaid diagrams, sketches, screenshots
  • @-mention any of them in a prompt: "build the page in @sketch"
  • The AI draws too: "draw the architecture on the canvas"
  • Your pitch notes live next to the code that backs them
½

5 · The whole team, one workspace

drawa --net .
  • Prints a link + QR code: teammates and phones join the same canvas
  • Token-protected. Trusted Wi-Fi only; treat the link like a password.
  • drawa https://github.com/owner/repo: clone and open in one go
½

6 · No Claude subscription? Fine.

  • Runs Claude Code, OpenCode and Codex
  • OpenCode has free models, no API key needed
  • Same canvas, same diffs, same approvals

Free models may train on what you send. Don't use them on code you can't share.

When it breaks + last 3 hours

  • Paste the exact error. Two bad fixes → git restore .
  • Fresh session when it gets confused. Three strikes → cut or fake it.
  • Feature freeze 3h before the end. Deploy early. Seed fake data.
  • Review every diff on the canvas, rehearse twice, record a backup video.
